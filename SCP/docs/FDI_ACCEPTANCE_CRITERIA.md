# First Delivery Inspection (FDI) — SCP Acceptance Criteria

## Acceptance Criteria

1. Given a user whose role is Project Admin, when they view the Procurement Log or the FDI Listing page, then they see all Submittals they're otherwise permitted to see, regardless of Supplier Organisation.
2. Given a user who belongs to the project's Project-Owning Organisation (any role), when they view the Procurement Log or the FDI Listing page, then they see all Submittals they're otherwise permitted to see, regardless of Supplier Organisation.
3. Given a user who is not a Project Admin and does not belong to the Project-Owning Organisation and is not the Responsible user for a given Submittal, when they view the Procurement Log, then they only see that Submittal if their Organisation matches its Supplier Organisation.
4. Given a user who is not a Project Admin and does not belong to the Project-Owning Organisation and is not the Responsible user for the Submittal a given FDI is tied to, when they view the FDI Listing page, then they only see that FDI if their Organisation matches the linked Submittal's Supplier Organisation.
5. Given this Organisation-scoping filter, when it is applied to any user, then it narrows (via intersection) whatever Submittals that user's role permissions already allow them to see — it never grants visibility beyond what the role's own permissions allow, except as explicitly added by the Responsible-user grant in AC9–AC11.
6. Given a delivery on a Submittal triggers an FDI notification, when notifications are sent, then a user who is not a Project Admin, does not belong to the Project-Owning Organisation, and has not been identified as the Inspector for that FDI's Material, does not receive it — regardless of whether they are the Responsible user for the underlying Submittal.
7. Given a Project Admin or a user belonging to the Project-Owning Organisation, when FDI notifications are sent, then they continue to receive them exactly as today.
8. Given a Submittal with no Supplier (and therefore no Supplier Organisation) assigned yet, when a user who is not a Project Admin, does not belong to the Project-Owning Organisation, and is not the Responsible user for it views the Procurement Log or FDI Listing, then that Submittal is not shown to them, since it has no Supplier Organisation to match against.
9. Given a user has been assigned as the Responsible user for a Submittal, when they view the Procurement Log, then they can see, edit, and work with that Submittal regardless of their own Organisation.
10. Given a user has been assigned as the Responsible user for a Submittal, when they view the FDI Listing page, then they can View every FDI tied to a Material on that Submittal, regardless of their own Organisation.
11. Given a user is the Responsible user for a Submittal but has not been identified as the Inspector for a given FDI tied to that Submittal's Materials, when that FDI needs to be filled or a notification is sent for it, then that user cannot Fill it and does not receive the Notify event for it — Responsible status alone only grants View.
12. Given the Procurement Log, when a Project Admin selects a Submittal and assigns a Responsible user, then only users currently holding the Sub Contractor or Project Admin role are selectable, only a Project Admin can perform the assignment, the assignment replaces any previously assigned Responsible user for that Submittal, and it takes effect immediately for visibility/edit purposes per AC9–AC11.
13. Given a user who is the Responsible user for a Submittal has their role changed away from Sub Contractor/Project Admin, when this happens, then no automatic change is made to the Submittal's Responsible assignment — they remain Responsible until a Project Admin manually reassigns it to someone else.
